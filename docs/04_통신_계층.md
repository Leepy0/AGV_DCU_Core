# 통신 계층: 링크 추상화, ACS 효율화, WiFi 전환

## 1. 구조

```
            ┌──────────── acs (세션) ────────────┐   ┌── mgmt (관리) ──┐   ┌── fwup (FOTA) ──┐
            │ 슬롯 40칸, 재전송, 교차로, 스테이션 큐  │   │ 'M' 프레임 처리   │   │ 'F'/'R' 처리     │
            └──────────────┬─────────────────────┘   └───────┬────────┘   └───────┬────────┘
                           │ frame_t (종류, PAN, MsgID, AGV, 본문)                 │
            ┌──────────────┴──────────────────────────────────────────────────────┴────────┐
            │ frame: STX/ETX 코덱, BCC, 길이·종류·자리 검사, 종류별 디스패치, AGV ID 필터        │
            └──────────────┬────────────────────────────────────────────────────────────────┘
                           │ 바이트 스트림 (링 버퍼)
            ┌──────────────┴───────────────┐    ┌──────────────────────────────┐
            │ link_zb  SCI-A 38400 (지그비)  │ 또는│ link_wifi SCI-A 115200 (ESP32)  │   ← P_COMM_LINK
            └──────────────────────────────┘    └──────────────────────────────┘
```

- 링크 선택은 부팅 시 1회. `link_select(P_COMM_LINK)`가 보레이트·링크 전용 처리기(생존 프레임, RFID 바이트열 분리)를 설정한다.
- `frame` 위의 모듈은 링크를 모른다. 지그비든 WiFi든 같은 코드가 돈다.
- 수신 ISR은 바이트를 링 버퍼에 넣고, 프레임이 완성되면 **거리 스냅샷**과 함께 프레임 큐에 넣는다. 처리(`comm_poll`)는 10 ms 메인 루프.

## 2. 프레임 모듈

### 2.1 수신 파서 (링크 공통)

상태기계: `IDLE` → (STX) `BODY` → (ETX 또는 길이 초과) 판정.

| 검사 | 규칙 | 실패 시 |
|---|---|---|
| 길이 | 20바이트(STX~ETX) 또는 12바이트만. `F` 프레임은 11+2 | 폐기, `stat.len_err++` |
| 종류 | `E A W N C D F M`. 그 외 | 폐기, `stat.type_err++` |
| PAN·MsgID | `'1'~'9','A'~'F'`. 수신 MsgID `'0'`은 **허용**(구 ACS 호환). `E`의 MsgID는 보지 않는다(리더 보드가 `'Z'`를 보낸다) | 폐기 |
| AGV ID | `[4:5]` 숫자 2자리 == `P_AGV_ID`. 모든 종류에 적용 | 폐기, `stat.id_mismatch++` |
| BCC | 4비트 합 | `'T'` 프레임 형태면 RFID 재시도 후보 저장 뒤 폐기. 그 외 폐기 |
| 자리별 문자 | 종류별 자릿수 규칙(숫자 자리에 숫자) | 폐기 |

- STX 수신 시 진행 중 프레임 폐기 후 재시작. ETX가 `cnt <= 5`에서 오면 데이터로 취급(현행 유지).
- WiFi 링크: STX 밖에서 온 바이트는 "RFID 바이트열 후보"로 별도 버퍼에 모아 `rfid_raw` 처리기로 넘긴다. 형식 확인 전까지는 길이·시각만 기록한다.
- 체크섬이 4비트뿐이므로 위 검사 전부를 통과해야 유효로 본다.

### 2.2 송신 빌더

`frame_build(buf, type, info, num3, bat3)`: 20바이트 고정. 빈자리는 `'0'`. BCC는 type부터 17바이트 합. MsgID는 전체 공통 `'1'~'F'` 순환(송신 쪽 결정 사항).

송신 큐: 링 버퍼 255바이트, TX ISR이 비운다. 한 프레임은 쪼개지 않고 통째로 넣는다(큐 여유가 없으면 다음 10 ms로 미룸).

## 3. ACS 세션 (슬롯·재전송) 재설계

요구사항 §3.5의 새 규칙을 구현한다. 현재 코드의 CT² 간격과 선두 슬롯 대기(head-of-line blocking)를 없앤다.

```
슬롯: { info, num, bat, msgid, try_cnt, try_total, timer_ticks, active }  × 40
매 10 ms acs_schedule():
    for 각 active 슬롯: timer_ticks--
    후보 = timer_ticks <= 0 인 슬롯 중 가장 오래된 것 (생성 순번)
    후보가 있고 송신 큐에 여유가 있으면: 송신, try_cnt++, try_total++, timer = 간격 + 지터
        try_cnt % 10 == 0 이면 msgid 재발급
        try_total >= 99 이면 슬롯 해제, stat.give_up++
    (한 호출에 프레임 1개)
간격:
    일반 = P_ACS_RETRY_SEC > 0 ? P_ACS_RETRY_SEC × 100틱 : P_ACS_RETRY_LEGACY × 10틱
    교차로 = (P_CROSS_RETRY_100MS > 0 ? P_CROSS_RETRY_100MS : P_ACS_RETRY_SEC) × 10틱. 값이 0이면 50틱, 상한 500틱
    교차로 ACK 뒤 keep-alive = 500틱 (교체)
지터: xorshift32, 시드 = avalanche((PAN<<8)|AGV_ID), 폭 = max(간격/10, 3틱), 가산 전용
최초 송신: 슬롯 생성 다음 10 ms (timer = 0)
```

- `P_ACS_RETRY_LEGACY == 0`이면 ACS 통신을 쓰지 않는 장비다. ACS로 가는 슬롯과 응답을 만들지 않는다. 태그 리더 보드로 가는 `E` 프레임 ACK는 계속 보낸다.
- ACK 매칭은 Info 문자(변경 불가). 같은 Info의 활성 슬롯이 둘 이상이면 **가장 오래된 것**을 지운다.
- `'A'` 응답 슬롯(Call Ack, W/C ACK)은 1회 송신 후 해제. 재전송 없음.
- Cross-In/Out은 일반 스케줄러에서 제외하고 교차로 상태기계가 간격을 관리한다(요구사항 §3.6). Cross-Out 재전송이 Cross-In 카운터를 보던 버그, `retry_time` 공유 버그는 고친다.
- `gDA_Collision_Type`은 부팅 시 파라미터 읽은 직후 계산한다. 0이면 교차로 보고만 끄고 **다른 슬롯 송신은 막지 않는다**(현재는 전체가 막힘 — 동작 변경, 재검토 문서 3절 6번).
- `current_mode != AUTO`이면 송신하지 않는 규칙은 유지하되, `REMOTE` 모드(관리 프로토콜)에서는 상태 프레임만 허용한다.

## 4. 지그비 링크 효율화

지그비는 반이중·저대역폭이다. 송신 바이트 수와 재전송 횟수를 줄이는 것이 전부다.

| # | 방안 | 효과 | 비용 |
|---|---|---|---|
| 1 | 선두 대기 제거(3절) | 한 슬롯 무응답이 다른 보고를 막지 않음. 최초 송신 지연 최대 25 s → 10 ms | 없음 |
| 2 | 선형 간격 + 지터 | 같은 구역 AGV의 동시 재전송 충돌 감소 | 없음 |
| 3 | `'D'` 표시 보고 중복 억제 | 같은 번호 연속 보고 생략(마지막 송신값과 같고 ACK 받았으면) | 상태 1워드 |
| 4 | `'P'` 상태 보고 간격 파라미터화 | 60 s 고정 → `P_ERR_REPORT_MIN`과 통합 | 없음 |
| 5 | 오류 보고 `set[40]` 오버플로 수정 | 보고가 실제로 나감 | 동작 변경 |
| 6 | 재전송 포기 뒤 요약 로그 | 포기한 보고를 로그에 남겨 관리 프로토콜로 회수 | 로그 공간 |
| 7 | 수신 FIFO 오버런 실제 복구 | 프레임 손실 뒤 자동 복구 | 없음 |
| 8 | ACK 중복 수신 무시 | 같은 Info 연속 ACK는 첫 것만 처리 | 없음 |
| 9 | 송신 전 캐리어 감지 | **불가.** 투명 모듈이라 DCU가 채널 상태를 모른다 | — |
| 10 | 프레임 압축 | **불가.** ACS 형식 고정 | — |

통계(`stat`)는 관리 프로토콜로 조회한다: 송신·재전송·포기·ACK 지연 평균/최대·수신 오류 종류별.

## 5. WiFi 링크

- 바이트 스트림은 지그비와 같다. 다른 점은 (1) 보레이트 115200, (2) `F` 프레임 처리, (3) RFID 바이트열 혼입, (4) 생존 신호 필요, (5) 서버가 임의 프레임을 수동 전송할 수 있음(종류 `F`·`R` 제외).
- `F` 프레임은 `fwup_handle()`이 ACS 파서보다 먼저 본다(`01_아키텍처.md` 8절).
- 생존 신호: WiFi 링크에서는 관리 프로토콜 상태 프레임(`M` 종류)을 2초마다 보낸다. 지그비 링크에서는 보내지 않는다(대역폭).
- 재전송 전략은 WiFi에서도 같다. 브릿지가 단절 중 프레임을 버리므로 DCU 재전송이 전달을 보장한다. 단 WiFi는 왕복이 빠르므로 `P_ACS_RETRY_SEC`를 사이트별로 더 짧게 둘 수 있다.
- 지연 목표(교통제어 0.5초)는 브릿지 문서 기준. DCU 쪽 추가 지연은 10 ms 스케줄러 1틱.

## 6. 관리 프로토콜 프레임 `M`

ACS 20바이트 프레임과 같은 링크를 타되 길이가 가변이다. 브릿지 제약(256바이트, ETX로 자름, 0x03 금지) 때문에 **ASCII만** 쓴다.

```
STX 'M' PAN MSG AGV(2) CMD(2) LEN(2, ASCII-HEX 바이트 수) PAYLOAD(ASCII-HEX, ≤ 200자) CRC16(4, ASCII-HEX) ' ' BCC ETX
```

- `CMD` 2자: 명령 코드(`05_게이트웨이_기능.md`).
- `CRC16`: CCITT-FALSE, `'M'`부터 PAYLOAD 끝까지. 4비트 BCC를 보강한다.
- 응답은 같은 형식, `CMD`의 둘째 자를 소문자로(`PR` 요청 → `Pr` 응답). MsgID는 요청값 그대로.
- 게이트웨이는 `M`을 ACS로 올리지 않고 서버 안에서 소비한다(`AgvFrame.IsForAcs` 화이트리스트에 `M` 추가 필요). 수동 전송 화면에서 `M`을 보낼 수 있게 하되 주행 영향 명령은 확인창.
- 지그비 링크에서도 `M`을 받을 수 있다(파라미터 읽기·상태 조회 같은 비주행 명령). 조그·출력 강제·변위 이동은 WiFi 링크 또는 USB/BLE 브릿지 경유로만 허용한다(`P_COMM_LINK`로 판정).
- 기존 ACS·RFID 장비는 `M`을 모르므로 충돌이 없다. 게이트웨이 수동 전송의 종류 검증 규칙에 `M`을 등록한다.

## 7. 수신 처리 순서 (`comm_poll`, 10 ms)

1. 프레임 큐에서 1~4개 꺼낸다(큐 길이 4).
2. `fwup_handle()` — `F`면 여기서 끝.
3. AGV ID 검사.
4. 종류별:
   - `E`: 회전 중이면 무시(ACK 없음). 아니면 ACK 슬롯 생성 → 중복 판정 → 이력 갱신 → `'T'`면 거리 보정 후 태그 액션, 그 외 `I/O/D/B/C/S` 처리.
   - `W`: ACK 슬롯 → PAN 갱신 → `SC` 큐 리셋 / `C` 서브커맨드.
   - `A`: Info로 슬롯 해제(가장 오래된 것).
   - `N`: 스테이션 3개 append(상한 검사) → Call Ack 슬롯 → `DA_ACS_Next` → 재출발.
   - `C`(12바이트): 시작/정지/전후진/스테이션 추가.
   - `M`: `mgmt_handle()`.
   - `D`: 무시.
5. 태그 거리 보정: 큐에 든 스냅샷 `(L0, R0)`와 현재 `(L, R)`의 차를 `tagact_compensate()`에 넘긴다. RFID 재시도 보상도 같은 함수.

## 8. 시험

- 프레임 코덱: 프로토콜 레퍼런스의 테스트 벡터(`H`→`8`, `12345678`→`4`, `E3107I012245 `→`7`) 전수.
- 파서: 길이 오류, STX 중간 삽입, ETX 조기, BCC 오류, AGV ID 불일치, `F` 11자 규칙 위반 각 1건 이상.
- 슬롯 스케줄러: 슬롯 3개 동시 활성에서 무응답 1개가 다른 둘을 막지 않는지, 간격이 명세와 같은지, 99회 포기, MsgID 10회마다 재발급.
- 교차로: ACK 뒤 500틱 교체, 20회째 286, Cross-In/Out 독립.
- 링크 전환: `P_COMM_LINK` 0/1에서 보레이트·`F` 처리·생존 프레임 유무.
