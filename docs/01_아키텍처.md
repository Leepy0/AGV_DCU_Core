# AGV DCU 코어 아키텍처

- 대상 MCU: TI TMS320F2808 (C28x, 100 MHz, `int` 16비트, FPU 없음), 툴체인 TI C2000 CGT 18.12.2.LTS, CCS 9.x.
- 이 문서는 코어 라이브러리(`AGV_DCU_Core`)의 계층, 실행 모델, 모듈 경계, 메모리 예산, FOTA·브릿지 호환, 저장소 구성을 정한다.
- 사이트별 동작(시퀀스·태그·I/O 핀 배치)은 앱 저장소(`AGV_DCU_App`)에 둔다. 코어는 사이트 이름을 모른다.

## 1. 계층

```
┌─────────────────────────────────────────────────────────────┐
│ 앱 (사이트별, AGV_DCU_App)                                     │
│  site/<name>/seq_table.c   시퀀스·ACT 표 (C 매크로)             │
│  site/<name>/tag_table.c   태그 번호 → 동작 규칙                 │
│  site/<name>/io_map.h      입출력 별칭, 벨트 배선                │
│  site/<name>/custom.c      사용자 정의 함수 (표로 안 되는 것)     │
│  site/<name>/site_cfg.h    프로파일(차종) 선택, 기본 파라미터      │
├─────────────────────────────────────────────────────────────┤
│ 코어 서비스 (AGV_DCU_Core, 라이브러리)                           │
│  seq      시퀀스·ACT 인터프리터      tagact   태그 액션 API        │
│  run      런 조정(Auto_Run)          acs      ACS 세션·슬롯·재전송 │
│  mgmt     관리 프로토콜(게이트웨이)    guide    가이드센서           │
│  motor    피드백·속도 PI·S커브        stop     MotorStop 상태기계   │
│  steer    조향 PI·칼만               branch   분기·테이프 정지·회전 │
│  param    파라미터·한계·파생값        keep     KEEP 변수            │
│  ui       키·7seg·램프·부저          log      링 버퍼 로그          │
├─────────────────────────────────────────────────────────────┤
│ 통신 링크                                                     │
│  frame    STX/ETX 코덱, 체크섬, 20/12바이트 파서 (링크 무관)       │
│  link_zb  SCI-A 지그비               link_wifi SCI-A ESP32 브릿지  │
│  link_sel 파라미터로 링크 선택                                    │
├─────────────────────────────────────────────────────────────┤
│ HAL (F2808 전용)                                               │
│  hal_timer  hal_sci  hal_ecap  hal_spi_dac  hal_adc  hal_eeprom │
│  hal_bus(2 ms 멀티플렉스 I/O)  hal_wdog  hal_flash(FOTA)         │
└─────────────────────────────────────────────────────────────┘
```

- 앱은 코어의 **공개 헤더**(`include/agv/*.h`)만 포함한다. 코어 내부 전역에 직접 접근하지 않는다.
- 레거시 앱 코드(`run_process_DA.c` 양식)를 그대로 쓰는 동안은 `include/agv/legacy_compat.h`가 옛 이름을 매크로·extern으로 제공한다. 이 헤더는 전환 기간 전용이며 새 코드는 포함하지 않는다.
- HAL은 레지스터 접근을 전부 감싼다. 호스트(PC) 빌드에서는 `hal_host/`가 같은 함수를 가짜로 제공해 시뮬레이션·단위 시험을 돌린다.

## 2. 실행 모델

| 문맥 | 주기 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| Timer0 ISR | 2 ms | 버스 입력 읽기, 키스캔, 7seg 한 자리, `tick2ms++`, 5회마다 `tick10ms++` | 제어, 통신 처리, EEPROM |
| eCAP1/2 ISR | 펄스 | 주기 캡처, 펄스 카운터, 거리 카운터, 회전 각 카운터 | 그 외 |
| SCI-A RX ISR | 바이트 | 링 버퍼 적재. 프레임 완성 시 `(프레임, Total_length, 좌·우 펄스)` 스냅샷을 프레임 큐에 적재 | 체크섬 이후 처리 |
| SCI-B RX ISR | 바이트 | 링 버퍼 적재, 마지막 바이트 수신 시각(`hal_cycles`) | 파싱 |
| SCI TX ISR | 바이트 | 링 버퍼 → TXBUF | |
| main 루프 | 연속 | `tick10ms`를 보고 10 ms 작업을 순서대로 실행. 남는 시간에 EEPROM 큐 1건, 로그 flush, 워치독, 가이드 센서 응답·스캔 주기 시험(t3.7·t3.8 `gresp_poll`, 개발 이미지만) | |
| CPU Timer1 | 자유 | `hal_cycles()` 자유 카운터(100 MHz, 인터럽트 없음). 응답 시간 측정 | |

10 ms 작업 순서(고정):

1. `comm_poll()` — 프레임 큐 처리. AGV ID 검사 → ACK 송신 요청 → 종류별 처리. 태그 프레임은 거리 보정 후 태그 액션.
2. `guide_poll()` — SCI-B 응답 파싱, 타임아웃 판정, `Guide_ReadData`·LED 갱신.
3. `run_coordinate()` — 런 조정(방향 전환, 회전, 대기 시작, 시퀀스 디스패치, 유휴 판정, KEEP 변경 감지 → 저장 큐).
4. `motor_run()` — 피드백 갱신 → (20 ms) 조향 → MotorStop 또는 주행 단계 → 속도 PI → DAC.
5. `seq_run()` — 활성 시퀀스 한 스텝 평가. 이어서 `act_run()` — 주행 중에도 도는 ACT 슬롯 평가.
6. `app_manual()` — 사이트 사용자 정의 (옛 `DA_Manual_Act`).
7. `ui_run()` — 키 처리, 표시 모드, 램프·부저.
8. `acs_schedule()` — 송신 슬롯 1개 처리.
9. `mgmt_poll()` — 관리 프로토콜 명령 처리(게이트웨이·CFG 매니저).
10. `io_write()` — 출력 버스 쓰기.

- 10 ms 작업이 끝났을 때 `tick10ms >= 2`이면 `overrun_cnt++`와 로그. 이 값은 관리 프로토콜로 조회한다.
- 시간 단위를 쓰는 앱 코드와 테이블은 **10 ms 틱**을 전제한다. 주기는 바꾸지 않는다.
- 태그 거리 보정: 수신 스냅샷 `(L0, R0)`와 처리 시점 `(L, R)`의 차 `d = 전진 ? L−L0 : R−R0`를 정지 거리에서 뺀다. RFID 재시도 보상(요구사항 §3.7)과 같은 함수 `tagact_compensate(d)`를 쓴다.

## 3. 모듈 경계와 소유 상태

각 모듈은 자기 상태를 `static`으로 소유하고, 다른 모듈은 접근 함수로만 읽는다. 앱과 레거시 코드가 쓰는 전역은 `legacy_compat.h`에서만 노출한다.

| 모듈 | 소유 상태 | 공개 API (발췌) |
|---|---|---|
| `param` | `set[]`, 한계 표, 파생값(`Target_speed`, `Low_Speed`, 펄스 스케일) | `param_get(idx)`, `param_set(idx, v)`(한계 검사·파생값 재계산·저장 큐), `param_default(kind)` |
| `keep` | KEEP 변수와 섀도 | `keep_get/set`, `keep_flush_if_changed()` |
| `storage` | EEPROM 저장 큐 | `storage_request(addr, val)`, `storage_poll()` |
| `motor` | rpm 피드백, 속도 PI, S커브, 주행 단계, `vin_out` | `motor_set_target(rpm)`, `motor_run()`, `motor_rpm(i)` |
| `stop` | MotorStop 상태기계 | `stop_request_tag()`, `stop_request_rapid(reason)`, `stop_run()` |
| `steer` | 조향 PI·칼만, `Add_speed[2]` | `steer_run(guide, vcmd)` |
| `guide` | 수신 파서, LED 덩어리 추적, 두절 판정 | `guide_feed(byte, rx)`, `guide_track(rx, branch, backward, out)`, `guide_on_request()`, `guide_on_sensor_switch()`, `guide_on_run_start()` |
| `branch` | 분기 단계 | `branch_run()`. 테이프 회전 정렬은 `motor_turn_adjust()` |
| `run` | `Flag_stopping`, `Flag_Ready/run`, `Flag_control`, `Traveling_step`, 대기 시작 | `run_coordinate()`, `run_request_restart(sec)`, `run_is_idle()` |
| `tagact` | 태그 액션 (정지·속도·방향·회전·분기·대기) | `tagact_stop()`, `tagact_speed(level)`, `tagact_forback(fb)`, `tagact_turn(dir, deg, fb, autostart, obs)`, `tagact_branch(dir)` |
| `acs` | 슬롯 40칸, 재전송 타이머, 교차로 상태, 스테이션 큐 | `acs_report(info, num)`, `acs_cross_in(id)`, `acs_schedule()`, `acs_station_push(n)` |
| `frame` | 파서 상태 | `frame_feed(byte)`, `frame_build(buf, type, info, num, bat)`, `frame_checksum()` |
| `link` | 활성 링크 | `link_select(kind)`, `link_send(buf, n)`, `link_rx_byte()` |
| `seq` | 활성 시퀀스, ACT 슬롯 4개, 슬롯별 타이머 | `seq_request(id)`, `seq_run()`, `seq_abort_all()`, `act_start(id)`, `act_run()`, `act_abort_all()` |
| `io` | 논리 입력/출력 비트맵, 매핑 표 | `io_in(id)`, `io_out(id, v)`, `io_force(id, v, ms)` |
| `ui` | 모드, 키 버퍼, 표시 버퍼 | `ui_run()`, `ui_mode()` |
| `err` | `system_err`, `stop_err`, `action_err` | `err_set_system(code)`, `err_clear(kind)` |
| `mgmt` | 관리 세션 상태 | `mgmt_poll()` |
| `log` | 링 버퍼 | `log_event(code, a, b)`, `log_read(...)` |

주행 제어 입출력은 `agv_drive`(`agv/drive.h`)와 `param_dv`(`agv/param.h`) 두 구조체에 둔다. `motor`·`stop`·`steer`·`branch`와 `run`·`guide`·`ui`가 함께 읽고 쓰는 레거시 전역을 그대로 옮긴 경계라서 위 "접근 함수만" 규칙의 예외다. `legacy_compat.h`도 이 필드로 옛 이름을 잇는다.

### 3.1 가이드센서

- 일반 센서는 좌우 16 LED, wide 센서는 좌우 32 LED + 세로 4 LED(T자)다. 세로 LED는 좌우 위치 계산에 넣지 않는다.
- 전진용·후진용 센서는 같은 SCI-B를 쓰고 `AGV_BACK` 릴레이로 전원을 바꾼다. 동시에 읽을 수 없다. 전환 뒤 `guide_on_sensor_switch()`가 파서, 이전 위치, 덩어리 상태, 오류 카운터를 지운다. 앞 센서의 마지막 위치로 뒤 센서 덩어리를 고르지 않기 위해서다. `invert`는 센서별 설정이다.
- 위치 소스는 `'h'` 전용이다(v0.31.0 표준). `GSR`(`P_GUIDE_CURVE_DETECT`)은 미사용이고 값은 무시한다. 예전 `'a'` 소스는 `LG` b9(`QUIRK_SRC_A`, 512)로만 되살린다(레거시 대조·원인 분석용). 튜닝 측정 구간은 소스와 무관하게 `'A'`/`'H'`를 번갈아 배율을 잰다.
- `'h'` 소스의 위치: 연속 점등 구간(덩어리)을 찾아 분기 지시 중이면 지시 방향 끝 덩어리, 그 외 이전 위치에 가장 가까운 덩어리를 고른다. 일반 `시작칸 + 끝칸 - 17`, wide `시작칸 + 끝칸 - 33`(칸 번호 1부터). `'a'` 값과 같은지와 부호는 실측 전이다.
- 필터(최소 폭, 최대 폭, 스캔당 변화량)는 기본값이 전부 꺼짐이다. 실측 없이 켜면 정상 테이프를 버려 정지할 수 있다.
- 조향의 커브 판정: `'a'` 소스(`QUIRK_SRC_A`)는 레거시 판정(점등 4칸 이상) 그대로다. `'h'` 소스(기본)는 덩어리 폭과 `curve_span`(기본 4)을 비교한다. 테이프 폭이 10\~25 mm라 LED 약 1\~4칸을 덮기 때문이다.
- 통신 두절(255): 전환 또는 시작 뒤 첫 유효 응답 전에는 판정하지 않는다. 그 구간은 준비 시간 초과(257)가 맡는다. 무응답은 요청을 보낸 스캔에서만 세고 3회 연속(30 ms, `P_GUIDE_TIMEOUT`으로 조정), 체크섬 실패는 10회 연속이다. 깨진 프레임은 응답으로 본다.

## 6. 통신 링크 추상화

상세: `04_통신_계층.md`.

- ACS 프로토콜(프레임·체크섬·ACK·재전송)은 링크와 무관하다. `frame`·`acs`는 바이트 스트림만 다룬다. 브릿지는 ACS 프레임을 바꾸지 않고 UDP로 투명 중계한다(ACK·재전송·MsgID는 DCU 책임, WiFi 단절 중 DCU→서버 프레임은 폐기됨).
- `link_zb`: SCI-A 38400 8N1, 지그비 모듈 투명 전송. 현재 동작 그대로.
- `link_wifi`: SCI-A(J4, RS-232 레벨) 115200 8N1(브릿지 `main_baud` 기본값)로 ESP32-S3 브릿지에 연결. 브릿지가 DCU에 직접 보내는 프레임은 `F`(11자, 버전 조회·업데이트 진입)뿐이며 DCU는 `R`로 답한다. 브릿지→DCU 방향으로 ACS 하향 프레임과 RFID 리더 원본 바이트가 같은 UART에 프레임 단위로 번갈아 나오므로 파서는 STX..ETX 프레임과 그 밖의 바이트열을 구분해야 한다(RFID 바이트열 형식은 확인 필요). 프레임 최대 256바이트, 프레임 안에 0x03 금지(브릿지가 ETX로 자른다).
- 선택: 파라미터 `P_COMM_LINK`(0 = 지그비, 1 = WiFi 브릿지). 부팅 시 읽어 보레이트·링크 핸들러를 고른다. 운전 중 전환은 하지 않는다.
- 두 링크 모두 같은 SCI-A를 쓰므로 하드웨어 변경 없이 모듈 교체만으로 전환한다. 보레이트는 링크별 상수이며 `P_INTERFACE_MODE`의 보레이트 선택(2\~7 → 9600, 8 → 115200 8N2)은 지그비 링크에서만 유효하다.

## 7. 관리 프로토콜 (게이트웨이·CFG 매니저)

상세: `05_게이트웨이_기능.md`.

- ACS 20바이트 프레임은 그대로 둔다. 관리 명령은 **별도 프레임**(`'$'` 시작, 길이 필드, CRC-16, 바이너리 페이로드)으로 같은 링크를 탄다. 기존 ACS·RFID 장비는 `'$'` 프레임을 보지 못하므로 충돌이 없다.
- 지그비 링크에서도 관리 프레임을 허용하되, 주행 중 명령(조그·출력 강제)은 WiFi 링크 또는 USB/BLE 브릿지에서만 받는다(대역폭·지연 때문).
- 안전 규칙: 조그·변위 이동·출력 강제는 `REMOTE` 모드에서만, 데드맨 500 ms, E-STOP·범퍼·STOP 스위치가 항상 우선.

## 8. FOTA·브릿지 호환

브릿지(`AGV_Wifi_Bridge` v0.9.1)·게이트웨이(`AGV_FOTA_GATEWAY` v0.7.1) 기준. 조사 근거는 `AGV_DCU_App/analysis/interface_report.md`.

- 방식: 플래시 섹터 A(0x3F4000)의 상주 부트로더 + 브릿지가 UART로 직접 프로그래밍("B안"). A/B 슬롯·자동 롤백 없음. 서버가 F 프레임으로 블록을 보내던 `DSP_OTA` 레포는 보관됨(사용하지 않음).
- 앱 링커(`AGV_Wifi_Bridge/dsp/app/F2808_app_example.cmd` 기준): `APPHDR` 0x3E8000(64워드, 패커가 채움), `codestart` 0x3E8040, `FLASHAPP` 0x3E8042\~0x3F3FFF(코드 최대 49,088워드), `RAMM1` 길이 0x3FA(0x7FA\~0x7FF는 부트 카운터·부트플래그), 0x3F4000 이상 사용 금지, CSM 비밀번호 0xFFFF 유지. 이 저장소의 `cmd/F2808_app_ota.cmd`가 이를 소유한다.
- 앱이 구현할 것(`app_fwupdate.c` 이식): `fwup_handle()`을 **다른 파서보다 먼저** 호출해 `F` 11자 프레임(`V000` 버전 조회, `U000` 업데이트 진입)에 `R` 프레임으로 2초 안에 응답. `F`는 ACS ACK·중복 판정·MsgID 로직과 분리하고 `A` ACK를 보내지 않는다. 안전 확인 콜백(0 안전, 1 주행, 2 충전, 3 전압, 4 오류, 9 기타)은 코어 `run`·`err` 상태로 구현. `UOK` 송신 완료(TXEMPTY) 뒤 `fwup_reset()`. 초기화 완료 시 `fwup_boot_ok()`. 앱 워치독 필수.
- 생존 판정: 브릿지는 "최근 3초 안에 STX로 시작하는 8바이트 이상 프레임"으로 앱 생존을 본다. WiFi 링크에서는 3초보다 드물게 보내지 않도록 주기 상태 프레임(관리 프로토콜)을 2초 간격으로 보낸다.
- 앱 버전 문자열은 1\~8자 `[A-Za-z0-9._-]`. 빌드 후처리 `dsp_pack.py bundle`로 `.out`·`.map`을 포함한 `.dsppkg`를 만든다. Release도 `-g` 유지. `.out`에 소스를 내장하는 pre-build(`embed_src`)는 앱 저장소 빌드에서 유지한다.
- **플래시 섹터:** F2808은 16K워드 섹터 4개다(D 0x3E8000, C 0x3EC000, B 0x3F0000, A 0x3F4000). 부트로더 ERASE의 `SECTORB|SECTORC|SECTORD`와 앱 영역 0x3E8000\~0x3F3FFF는 이 구조와 맞다. `SPRS230` 메모리 맵 그림과의 최종 대조는 실기 FOTA 전에 한다.
- OTA 이전 시험은 `cmd/F2808_app_direct.cmd`로 링크해 JTAG로 직접 굽는다. 이 경우 앱이 플래시 전체를 쓰고 부트로더는 지워진다.
- 부팅 지연: 부트로더 HELLO 창 때문에 매 부팅 약 0.2초 늦다. 기동 시간 규격과 충돌 여부를 사이트에서 확인한다.

## 9. 버전

- 코어 라이브러리: `vMAJOR.MINOR.PATCH`. 공개 헤더가 바뀌면 MINOR, 호환이 깨지면 MAJOR.
- 앱 펌웨어: `사이트코드-YYMMDD-N`과 코어 버전, git 짧은 해시를 이미지 헤더와 `mgmt` 조회에 넣는다.
- `set[47] VERSION`은 호환을 위해 남기되 값은 빌드 시 주입(`YYMM` 10진수). 8진수 리터럴 실수는 사라진다.

## 10. 저장소와 릴리스

| 저장소 | 공개 | 내용 | 릴리스 |
|---|---|---|---|
| `AGV_DCU_Core` | 공개 | 코어 소스, 공개 헤더, HAL, 호스트 시뮬레이터, 단위 시험, 문서 | GitHub Releases에 `agv_dcu_core-<ver>.zip` = `lib/agv_dcu_core.lib` + `include/agv/` + `cmd/` + `CHANGELOG.md` |
| `AGV_DCU_App` | 사내 | 사이트 폴더, 테이블, 사용자 정의 스텝, CCS 프로젝트, 레거시 아카이브, 분석 보고서 | 사이트별 `.out` + 이미지 |

- 앱은 코어를 **벤더링**한다: `third_party/agv_dcu_core/<ver>/`에 릴리스 zip을 풀어 커밋한다. 사내 빌드는 외부 호스트에 접속하지 않는다.
- 코어 라이브러리 빌드: `cl2000`로 오브젝트 생성 → `ar2000 -r`로 `.lib`. 스크립트 `tools/build_lib.cmd`. 같은 소스를 호스트 gcc로 빌드해 단위 시험(`tests/`)을 돈다. GitHub Actions는 호스트 시험만 돌린다(TI 툴체인은 재배포 불가).
- 코어에 사이트 식별자·AGV ID·고객명은 넣지 않는다. 예제는 가상의 사이트 `example`만 둔다.
