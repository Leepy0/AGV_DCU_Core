# 네이밍 표준

목적: 같은 뜻을 가진 이름이 여러 가지로 흩어져 있는 상태(`Loading_Ready_Flag`, `Last_Loading_Flag`, `FL_check`, `Gate1_Out`, `cnt_1`…)를 하나의 규칙으로 정리한다. 레거시 이름은 `legacy_compat.h`로 전환 기간 동안만 유지한다.

## 1. 일반 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 모듈 접두사 | 소문자 모듈명 + `_` | `motor_`, `stop_`, `steer_`, `guide_`, `acs_`, `seq_`, `io_`, `param_`, `keep_`, `ui_`, `err_`, `mgmt_`, `link_`, `frame_`, `hal_` |
| 함수 | `모듈_동사_목적어()` | `stop_request_tag()`, `acs_report_arrive()`, `io_set_out()` |
| 전역(모듈 밖 노출) | 노출하지 않는다. 접근 함수만 | `motor_rpm(0)` |
| 모듈 내부 상태 | `static` 구조체 하나 `s_모듈` | `static struct motor_state s_motor;` |
| 상수·매크로 | 대문자, 모듈 접두사 | `STOP_MIN_RPM`, `ACS_SLOT_COUNT` |
| 열거형 | 타입 `모듈_것_t`, 값 `모듈_것_값` | `stop_reason_t`, `STOP_REASON_TAG_POSITION` |
| 구조체 | `모듈_것_t` | `seq_step_t` |
| 파라미터 인덱스 | `P_이름` | `P_DRIVING_SPEED`, `P_ACS_RETRY_TIME` |
| 오류 코드 | `ERR_이름` = 기존 숫자 고정 | `ERR_GUIDE_RANGE_OVER = 257` |
| 논리 입력 ID | `IN_이름` | `IN_START_SW`, `IN_EXT_1`, `IN_LIFT_UP_LIMIT` |
| 논리 출력 ID | `OUT_이름` | `OUT_LAMP_R`, `OUT_EXT_1`, `OUT_BELT1_RUN` |
| 시퀀스 ID | `SEQ_대상_동작` | `SEQ_LOAD`, `SEQ_UNLOAD`, `SEQ_BOX_LOAD`, `SEQ_LOAD_FINISH`, `SEQ_LOAD_LAST`, `SEQ_LOAD_EMPTY`, `SEQ_LOAD_PART`, `SEQ_CART_LOAD`, `SEQ_TROLLEY_LOAD`, `SEQ_MATERIAL_UNLOAD` |
| 태그 액션 | 표에서 `A_동작`, 코드 값은 `TA_동작` | `A_STOP`, `A_SPEED_LOW`, `A_FORBACK(TOGGLE)`, `A_TURN(CW, 90, 0, 1, 0)`, `A_SEQ(SEQ_LOAD)`, `A_ACT(id)` |
| 단위 접미사 | 값의 단위를 이름에 | `_rpm`, `_mm`, `_pulse`, `_ticks`(10 ms), `_ms`, `_dv`(0.1 V) |
| 불리언 | `is_`, `has_`, `_on` | `run_is_idle()`, `guide_all_off` |
| 활성 극성 | 논리 I/O는 **항상 1 = 활성**. 물리 핀의 active-low는 `io_map`에서 흡수 | 앱 코드에 `nON/nOFF`가 나오지 않는다 |
| 파일 | 모듈명 = 파일명 | `src/stop.c`, `include/agv/stop.h` |
| 사이트 | 소문자 약어 | `site/<name>/` (앱 저장소 전용. 코어에는 없음) |

금지: 접두사 `g`/`n`/`DA_`/`Flag_` 혼용, 오타가 굳은 이름(`gCnt_stop_lenght`, `Inital_start`, `Fowad`, `Gete_Out`), 의미가 바뀐 이름(`CHARGE_TIME`이 재전송 시간, `ACTUATOR_DELAY`가 속도).

## 2. 시퀀스 요청 플래그 통일

현재 20여 개 `int` 플래그가 "시퀀스 요청"을 뜻한다. 새 코어는 **요청 비트셋 + 활성 시퀀스 ID**로 바꾼다.

| 레거시 | 새 ID | 뜻 |
|---|---|---|
| `Loading_Ready_Flag` | `SEQ_LOAD` | 적재 |
| `Unloading_Ready_Flag` | `SEQ_UNLOAD` | 하역 |
| `Box_Loading_Ready_Flag` | `SEQ_BOX_LOAD` | 박스 적재 |
| `Box_Unloading_Ready_Flag` | `SEQ_BOX_UNLOAD` | 박스 하역 |
| `Finish_Loading_Flag` | `SEQ_LOAD_FINISH` | 적재 마무리 |
| `Finish_Unloading_Flag` | `SEQ_UNLOAD_FINISH` | 하역 마무리 |
| `Last_Loading_Flag` | `SEQ_LOAD_LAST` | 마지막 적재 |
| `Last_Unloading_Flag` | `SEQ_UNLOAD_LAST` | 마지막 하역 |
| `Empty_Loading_Flag` | `SEQ_LOAD_EMPTY` | 빈 용기 적재 |
| `Empty_Unloading_Flag` | `SEQ_UNLOAD_EMPTY` | 빈 용기 하역 |
| `Part_Loading_Flag` | `SEQ_LOAD_PART` | 부분 적재 |
| `Part_Unloading_Flag` | `SEQ_UNLOAD_PART` | 부분 하역 |
| `Cart_Loading_Flag` / `Cart_Unloading_Flag` | `SEQ_CART_LOAD` / `SEQ_CART_UNLOAD` | 대차 |
| `Trolley_Loading_Flag` / `Trolley_Unloading_Flag` | `SEQ_TROLLEY_LOAD` / `SEQ_TROLLEY_UNLOAD` | 트롤리 |
| `Material_Unloading_Flag` | `SEQ_MATERIAL_UNLOAD` | 자재 하역 |
| `Loading_Check_Flag` | `SEQ_LOAD_CHECK` | 적재 확인 |
| `Sort_1~5_Flag`, `Load_1~10_Flag`, `Unload_1~10_Flag`, `Check_1~5_Flag`, `Turn_1~5_Flag`, `Wait_1~5_Flag` | `SEQ_SORT(n)`, `SEQ_LOAD_N(n)`, … | 번호 시퀀스. 활성 사이트에서 사용 0건이면 제거 |
| `Lifter_Act_Flag`, `Start_act_Flag`, 사이트 전용 플래그 | 사이트 사용자 정의 상태 | 코어 계약 아님. 앱 파일 안에서만 |
| `Gate1~8_Out`, `FL_check` | 주행 중 출력 패턴이면 ACT(`A_ACT(id)`), 그 외는 사이트 상태(`SET_STATE`) | 이름이 "출력"이지만 실제는 상태 변수이고 뜻이 호기마다 다르다. 변환 때 경로별로 나눈다 |
| `gAction_Step` | `seq` 내부 `step` | 시퀀스 1개가 활성일 때만 의미. 사용자 정의 스텝은 인자로 받음 |
| `cnt_1 … cnt_9` | 스텝 전용 타이머(시퀀스·ACT 슬롯별), 사용자 정의는 `seq_ctx_t.timer` | 시퀀스와 수동 동작이 같은 카운터를 공유하던 문제 해소 |
| `Flag_Wait_Start`, `Cnt_Wait_Start` | `run_request_restart(sec)` | "재출발 예약" 한 함수 |
| `DA_Guide_Stop_Action = &Flag` | `tape_stop_request(SEQ_id)` | 포인터 대신 시퀀스 ID |

우선순위: 요청 비트셋이 여럿이면 레거시 `Auto_Run_Process` 분기 순서(로딩류 → 언로딩류 → 번호 → 사용자 정의)를 ID 숫자 순서로 고정한다. 테이블 생성기는 이 순서를 지킨다.

## 3. 입출력 이름

물리 핀 이름(`EXT_IN13`, `INTERFACE_OUT1`)과 뜻 이름(`Position_Sen`, `Interface1`)이 사이트마다 다르게 묶여 있다. 새 구조는 세 층이다.

| 층 | 이름 | 소유 |
|---|---|---|
| 물리 | `PIN_IN_A0..7`, `PIN_IN_B0..7`, `PIN_EXT_IN_1..16`, `PIN_OUT_LAMP_0..7`, `PIN_EXT_OUT_1..16` | 코어 HAL(보드 고정) |
| 논리 | `IN_START_SW`, `IN_STOP_SW`, `IN_ESTOP`, `IN_BUMPER_1/2`, `IN_OBS_F/B`, `IN_TAG_L/R`, `IN_REMOTE_START/STOP`, `IN_EXT_1..16`, `OUT_AMP_*`, `OUT_LAMP_R/Y/G`, `OUT_BUZZER`, `OUT_AGV_BACK`, `OUT_BRAKE_1/2`, `OUT_IF_1/2`, `OUT_EXT_1..16` | 코어(보드 공통 의미) |
| 사이트 별칭 | `#define LIFT_UP_LIMIT IN_EXT_9`. 미연결은 `IO_NONE` | 앱 `site/<name>/io_map.h` |

- 앱 테이블은 논리 ID 또는 사이트 별칭만 쓴다. `Output_Spare.bit.First_Power` 같은 비트필드 이름은 사라진다.
- 레거시 `First_Belt_On_Off_Process(InOut, OnOff)`는 표의 `BELT_ON(n, CW)`·`BELT_ON(n, CCW)`·`BELT_OFF(n)`으로 통일한다. 방향별 출력은 `io_map.h`의 `BELTn_CW`·`BELTn_CCW` 마스크로 정하며 1개든 2개든 된다.
- 논리 ID는 0~31이 표에서 쓰는 신호이고 앰프 신호는 32 이상이다(`io.h`). 극성은 active-low가 기본이고 반대 배선만 `io_map_t`에 등록한다. 앱 코드에는 `nON`이 없다.

- `P_GUIDE_CURVE_DETECT`: 0 끔(`'a'` 소스), 1 `'A'`:`'H'` 혼합, 2 `'h'` 전용. 위치 소스 선택을 겸한다.
- `P_LEGACY_QUIRKS`: 비트를 켜면 고치기 전 동작을 재현한다. 0이면 고친 동작이다(`07_주행_조향_성능.md` 1절). 위 표의 "기본값 0이면 레거시 동작"에서 이 번호만 예외다.

현장 장비에는 이 번호에 0이 아닌 값이 저장돼 있으므로 **1회 초기화**가 필요하다. EEPROM 주소 50(미사용)을 배치 표시로 쓴다. 부팅 때 읽은 값이 표시값이 아니면 31·38·39·44를 0으로 쓰고 체크섬을 다시 계산해 쓴 뒤, 읽기 검증이 끝나면 마지막에 표시값을 쓴다. 표시를 마지막에 쓰므로 도중에 전원이 끊겨도 다음 부팅에서 다시 수행한다. 주소 50은 체크섬 범위 밖이다.

## 7. 레거시 호환 헤더

`include/agv/legacy_compat.h`는 다음만 제공한다.

- 옛 전역 이름 → 코어 접근자 매크로(읽기 전용인 것은 함수 호출로, 쓰기가 필요한 것은 코어가 노출하는 호환 변수로).
- 옛 함수 이름 → 새 함수(`#define DA_ACS_Loading(n) acs_report(ACS_INFO_LOADING, n)`).
- 옛 플래그 → `seq_request_flag[SEQ_id]` 배열 원소(포인터 취득 가능).
- 옛 `Output_Spare.bit.X` → `io_out(OUT_X, v)` 매크로는 **대입식에 쓸 수 없으므로**, 호환 헤더는 `Output_Spare` 구조체를 그대로 제공하고 `io_write()`가 매 10 ms 끝에 구조체를 논리 출력으로 복사한다. 테이블로 전환된 사이트는 이 구조체를 쓰지 않는다.

호환 헤더는 코어 공개 API가 아니다. 버전 변경 시 호환을 보장하지 않으며, 레거시 블록이 모두 전환되면 삭제한다.
